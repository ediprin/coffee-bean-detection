# Thesis Proposal Foundation — v0.16.0

Date: 2026-08-25

Milestone: **equation numbering + mixed-orientation Table 2.1 hardening**.

## 1. Chapter-based display-equation numbering implemented

Created:

`tools/thesis/apply_equation_numbers.py`

The pass operates on Pandoc-generated native Word display equations (`m:oMathPara`) and intentionally ignores inline mathematics. Each display equation is converted into a borderless three-column row:

```text
balancing gutter | centered Word equation | (bab.nomor)
```

The numbering follows the SPs guide and restarts by chapter.

A synthetic native-OMML render was produced before the repository update. The resulting equations rendered centered with `(3.1)` and `(3.2)` aligned near the right text boundary on the same line.

## 2. Tabel 2.1 landscape isolation implemented

Created:

`tools/thesis/apply_landscape_tables.py`

The pass targets only the unique six-column `Tabel 2.1` related-work table and:

1. places its caption and table in an isolated next-page landscape section;
2. retains A4 with SPs 4/3/3/3 cm margins;
3. continues Arabic page numbering at the top-right;
4. restores portrait orientation after the table;
5. fixes the six-column width budget to 22.7 cm;
6. repeats the header row across pages.

The column allocation is:

```text
0.9 | 3.2 | 2.0 | 4.3 | 4.0 | 8.3 cm
```

for `No`, `Penulis & Tahun`, `Indeks`, `Fokus`, `Metode/Model`, and `Kontribusi/Gap` respectively.

## 3. Mixed-orientation pagination interaction tested

A synthetic multi-chapter DOCX was processed in the same order as the formal pipeline:

```text
chapter pagination
    ↓
portrait → landscape table → portrait
```

Rendered evidence confirmed:

- the landscape table retained a top-right Arabic page number;
- numbering continued monotonically through the orientation transition;
- post-table text returned to portrait;
- the following chapter opening still placed its Arabic number at the bottom-right.

This validates the document-engineering mechanism, not the actual proposal layout.
